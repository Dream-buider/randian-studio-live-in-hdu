# 新生端明亮电影化视觉系统设计

## 1. 目标

将新生端从“冷蓝信号系统”调整为“燃点晨曦电影”：页面整体更明亮、更热烈，首屏具有电影片头级冲击力，后续阅读页面延续同一品牌温度，但不牺牲问题、回答、来源与免责声明的可读性。

成功标准：

- 用户进入页面后能立即感受到燃点工作室的热烈气质。
- `/`、`/questions`、`/chat`、`/guide` 与新生端弹层看起来属于同一套产品。
- 倒计时仍是全站唯一的重型动态场景。
- 问题卡、来源、状态、更新时间和免责声明的可信层级不被装饰干扰。
- 320px 宽度、640px 高度、刘海屏、软键盘和减少动态效果模式均可正常使用。

## 2. 范围

### 包含

- `/`：开学倒计时与进入问答入口。
- `/questions`：问题卡、翻题导航、直接提问入口和预览提示。
- `/chat`：问题上下文、回答、来源、加载、重试和空状态。
- `/guide`：四座新生指北信号站。
- `QuestionCatalog` 与 `AskSheet` 两类新生端弹层。
- 新生端共用的 BrandHeader、QuestionCard 及来源/状态展示在新生端容器中的样式。

### 不包含

- `/admin` 及其任何组件、布局、颜色或交互。
- Router、API、Mock 数据、服务端、数据库、审核逻辑和内容数据。
- `PRODUCT.md` 与 `DESIGN.md` 的改写。
- 新图片生成、外部素材下载、新字体或新运行时依赖。

## 3. 保护规则

以下内容不得改变：

- 燃点工作室 Logo 与 `LIVE IN HDU` 名称。
- 精确到秒的倒计时逻辑、目标时间、完成状态与无障碍计时语义。
- 问题卡信息结构、滑动与按钮行为、问题目录和继续提问流程。
- 回答请求、重试保护、来源、审核状态、更新时间和免责声明。
- 指北的四座信号站结构、社区来源声明和外链内容。
- 44px 最小触控面积、焦点管理、视觉视口处理与 WebGL 降级。

## 4. 设计判断

### 拒绝的方向

- 全站红橙渐变、发光按钮和持续粒子：热闹但阅读疲劳，也会显得模板化。
- 暖白底加普通珊瑚卡片：安全但缺少电影感，无法回应“方案三”。
- 把倒计时的重型动画复制到每页：会造成性能和注意力竞争。

### 最终方向

“明亮晨曦电影片头”：暖白纸张作为阅读底色，燃点珊瑚红统领操作与品牌强调，日光金只用于非文字的光照和能量轨迹，杭电蓝退到来源、可信状态和少量识别信息。

整体风格强度为 9/10；倒计时动态强度为 8/10，问题、回答和指北为 3–5/10；信息密度保持当前水平。

这次会刻意避开上一版的冷蓝、磷光和技术雷达感，转向暖日光、电影曝光和纸张字幕板。

## 5. 颜色系统

新生端颜色必须定义在学生页面作用域内，不能直接覆盖管理端依赖的全局变量。

- **晨光纸 `#FFF3E8`**：新生端页面底色，带暖色但不发黄。
- **字幕纸 `#FFF9F3`**：问题卡、回答卡与弹层主表面。
- **燃点珊瑚 `#D94B32`**：品牌强调、数字和装饰光。
- **燃点深红 `#C43A27`**：主要按钮底色，确保浅色文字对比度。
- **日光金 `#F0A23A`**：光晕、轨迹和非文字能量提示，不承载正文。
- **炭红墨 `#2E1C19`**：标题与正文主文字。
- **暖灰墨 `#765B54`**：次要说明和元信息。
- **可信蓝 `#214B73`**：来源链接、可信识别和杭电关联信息。
- **焦点青 `#0F7F94`**：键盘焦点边框，保持可见性。

珊瑚红是唯一主色。日光金属于同一暖色光照体系，可信蓝只承担语义角色，不能与主操作竞争。

## 6. 字体与材质

- 保留现有 `HDU Arrival Display`，只用于倒计时标题、数字、分隔符和少量数字进度；不假设字体子集包含全部中文标题。
- 问题、回答、指北和表单继续使用现有中文系统字体，通过 800/400 的字重差建立电影海报式层级。
- 卡片材质从冷白塑料感改成暖白字幕纸：轻微纸张噪点、暖色阴影、半透明细边和局部曝光高光。
- 不使用渐变文字、大面积磨砂玻璃、紫色辉光、侧边彩条或每段一个英文小标签。

## 7. 页面设计

### 7.1 倒计时 `/`

- 保留现有校园晨光插画与 Logo，将天空从深夜压暗改为日出前后的明亮暖蓝。
- WebGL 光束由冷色星轨改为暖白与珊瑚色曝光线，朝校园地平线汇聚。
- 倒计时卡成为四块竖直电影片名牌：暖白表面、顶部曝光线、珊瑚数字和深色单位。
- 三层雷达圆环减少技术仪表感，改成镜头光圈与胶片对焦刻度。
- 入口按钮保持底部拇指区域，改为深珊瑚色实体按钮，不使用渐变文字。

### 7.2 问题卡 `/questions`

- 保留现有布局和卡片信息顺序。
- 页面底色改为晨光纸，顶部 Logo 区增加短的暖色光带，主动作使用深珊瑚色。
- 问题卡使用字幕纸表面；进度像场记板编号，分类与可信信息保留清晰语义。
- 上一题/下一题继续是两个明确按钮。换题使用有方向的裁切换幕，而不是通用淡入。
- 固定提问按钮保持原位置与高度，使用深珊瑚色，不遮挡底部内容。

### 7.3 回答 `/chat`

- 页面使用与问题卡一致的晨光纸和字幕纸体系。
- 问题上下文是较轻的暖色“上一幕”面板，回答卡为主阅读表面。
- 答案不逐字播放；完整内容直接可读，只对整个回答卡做一次短距离入场。
- 来源、免责声明与失败状态继续使用各自语义色，并保证正文对比度。

### 7.4 指北 `/guide`

- 保留四座信号站和纵向路线。
- Hero 从深蓝信号控制台改成明亮的晨曦发射台：珊瑚到日光金的照明、炭红文字和少量可信蓝。
- 路线使用暖色能量轨道，滚动时光脉冲依次经过四站；站点未进入视口时也必须完整可读。
- 信号站卡片与全站字幕纸一致，按钮使用深珊瑚色，来源声明保持显眼。

### 7.5 弹层

- `QuestionCatalog` 与 `AskSheet` 像电影幕布从底部升起。
- 使用暖白表面、顶部抓手、深珊瑚确认按钮和清晰输入边框。
- 保留现有焦点圈、Esc/关闭、背景点击、软键盘和内部滚动行为。

## 8. 动效设计

全流程共享同一条缓动曲线，但不同页面只使用与任务相关的动效。

1. **首屏**：天空变亮，光束汇聚，标题与四块倒计时片名牌依次落位。
2. **进入问答**：新页面用一次短暂暖色曝光揭幕；不修改路由结构。
3. **翻题**：根据上一题/下一题方向做水平裁切换幕；展开答案只做高度与内容状态反馈。
4. **回答**：回答卡整体从柔和日光中进入，正文直接显示。
5. **指北**：滚动时暖色光脉冲沿路线依次点亮站点。
6. **弹层**：底部幕布式上升，关闭时原路返回。

动态预算：只有倒计时允许 WebGL。其余效果使用 CSS、原生滚动观察和现有 Vue 状态，不新增 GSAP、Three.js 或其他依赖。

减少动态效果模式下：停止 WebGL，移除光束、扫光和脉冲循环；所有标题、卡片、信号站和按钮直接显示最终构图。

## 9. 图片与来源

- `/brand/campus-dawn-welcome.webp`：项目内校园晨光插画，只用于倒计时氛围，不作为真实校园照片或证据。

不生成、不下载、不热链任何新图片。

## 11. 验证方案

### 自动测试

- 先为新增视觉结构、减少动态效果分支和新生端作用域补充失败测试。
- 运行全部 Web 测试，确保问题、回答、弹层、指北和倒计时行为不变。
- 运行正式构建与公开试用构建。
- 运行 `git diff --check`，确认未修改受保护文件与管理端文件。

### 浏览器验证

- 宽度：320、375、390、430px。
- 高度：640px 与 844px。
- 桌面：居中的手机画布，不生成第二套桌面信息架构。
- 状态：加载、空、失败、明确重试、展开答案、首末题禁用、目录、提问弹层。
- 环境：WebGL 正常、WebGL 失败、减少动态效果、微信类窄视口和软键盘。
- 检查横向溢出、底部按钮遮挡、控制台错误和动画掉帧。

## 12. 交付标准

- 四条新生端路由与两类弹层使用同一套暖色视觉系统。
- 首屏具有电影片头级表现，后续页面不复制重型动画。
- 所有原功能、语义、来源与内容边界保持不变。
- 管理端在 Git diff 和浏览器结果中均无视觉变化。
- 自动测试、构建和约定的浏览器尺寸验证通过后才可声明完成。
