# LIVE IN HDU 用户反馈优化设计

日期：2026-08-02

状态：用户已确认设计，等待书面规格复核

适用项目：`apps/freshman-mvp`

## 1. 背景与目标

团队收到了三类可复现反馈：

1. 用户端缺少“燃点工作室”品牌 Logo。
2. 手机端打开提问弹窗后，软键盘可能遮住输入框或发送按钮。
3. 回答虽然能保证非空，但在知识不足时可能退化成“广泛大学”的通用建议；例如“给个社团的建议”和“社团有什么作用吗”没有给出杭电社团的实际信息，也没有提供可直接打开的校方页面。

本次优化要把问答产品与已获批准的《杭电新生指北》融合，并使回答满足以下约束：

- 优先回答杭州电子科技大学的实际情况。
- 证据存在时，回答后直接给出安全、可点击的来源链接。
- 明确区分“杭电官方”“新生指北”和“网络线索”，不把社区内容冒充官方文件。
- 资料不足时仍返回答案并进入现有 FIFO 人工审核队列，不使用“未收录”等拒绝性话术。
- 保持第三阶段现有批注原文不变。

## 2. 已确认决策

- 品牌名称为“燃点工作室”。
- 使用用户提供的正式 Logo 原图，不改字、不重绘。原图为 86×80 PNG，首版只在不超过 40 CSS 像素的页眉场景使用；以后可原路径替换高清版本。
- 采用“前端目录与摘要 + 飞书章节直达 + 已审核内容进入知识库”的融合方式。
- 用户已批准当前《杭电新生指北》作为“已审核社区资料”导入知识库。
- 指北的规范来源页为：
  `https://rcncolp2ehkb.feishu.cn/wiki/J7o6wBiJVi36wJk2VSTcyyb1nDd`
- 指北不会被标记成杭州电子科技大学官方文件。
- 不把飞书页面实时抓取结果自动发布。每次更新必须形成快照、记录哈希和批准信息，再进入知识库。

## 3. 用户端信息架构

### 3.1 品牌页眉

问题卡、指北页和回答页共用品牌页眉：

```text
[燃点工作室 Logo]  LIVE IN HDU
                    杭电新生问答与指北
```

Logo 具备 `alt="燃点工作室"`，文字仍作为真实文本显示，避免图片加载失败后品牌和页面含义完全消失。

### 3.2 首页入口

保留现有问题翻页作为首页主体，在页眉下增加两个轻量入口：

- `常见问题`：保持现有翻页卡片、全部问题目录和自由提问。
- `新生指北`：进入新的 `/guide` 页面。

不把整份飞书文档复制成第二套编辑系统，避免双端维护漂移。

### 3.3 新生指北页

`/guide` 展示从获批快照整理出的一级目录与摘要：

- 开学准备
- 宿舍
- 生活与地图
- 教学区与校园设施

每个目录卡片包含：

- 1 至 2 句摘要；
- 主要子章节；
- `查看完整章节`链接，直达飞书对应锚点；
- 社区资料标识和快照更新时间。

页面明确提示：“本页为燃点工作室与社区成员整理的新生经验，校方政策以杭州电子科技大学最新通知为准。”

### 3.4 回答来源区

预设、知识库和联网回答统一在正文后展示“参考资料”。每条来源具有类型标签：

- `杭电官方`：`hdu.edu.cn` 及其受控子域名中的校方页面。
- `新生指北`：获批飞书指南及对应章节。
- `社区经验`：其他已审核团队资料。
- `网络线索·待核验`：第三阶段公开搜索结果。

来源标题可点击；URL 必须继续经过现有的 HTTP/HTTPS 安全校验。没有证据 URL 时不得编造链接，也不得把“去官网看看”包装成已经找到的参考资料。

## 4. 手机软键盘适配

提问弹窗继续使用底部抽屉形态，但布局基于“实际可视视口”而不是只依赖 `vh`：

1. 新增独立的可视视口适配单元，监听 `window.visualViewport` 的 `resize` 和 `scroll`。
2. 计算并写入弹窗使用的视口高度、顶部偏移和键盘遮挡量；不支持 `visualViewport` 的浏览器回退到 `100dvh` 和安全区变量。
3. 键盘打开时，提问面板最大高度限制在当前可见区域内，输入区自身可滚动，发送按钮始终位于键盘上方。
4. 文本框聚焦后执行一次延迟的 `scrollIntoView({ block: 'nearest' })`，处理微信内置浏览器的视口更新延迟。
5. 弹窗打开时锁定背景滚动，关闭时恢复原滚动位置和原焦点。
6. 保留现有 Escape、Tab 焦点循环和无障碍对话框行为。

不会通过固定机型高度或写死键盘像素值解决该问题。

## 5. 《杭电新生指北》入库与版本控制

### 5.1 获批快照

实现时将当前飞书内容整理为一份 UTF-8 Markdown 快照，存放到明确的知识导入目录，并建立现有审批清单记录：

- 标题：杭电新生指北
- 类型：community
- 适用年份：2026
- 规范来源 URL：飞书 Wiki 页面
- 批准状态：用户在 2026-08-02 明确批准
- 内容 SHA-256
- 快照时间和页面显示的最近修改时间

不得把页面评论、编辑者联系方式、飞书界面文字或无关 UI 文本作为知识正文导入。

### 5.2 章节来源

快照中的每个一级、二级章节附带规范来源锚点。知识库返回相应片段时，服务端提取该安全 URL 作为 `新生指北`来源，并从用户可见回答中移除内部元数据标记。

### 5.3 更新规则

- 飞书修改不会自动覆盖线上知识。
- 管理端显示当前快照哈希、导入状态、批准时间和来源链接。
- 发现新版本后先生成差异，再由人工确认，随后创建新知识版本。
- 旧版本保留审计记录，不能静默覆盖。

## 6. 杭电优先回答链路

### 6.1 第一阶段：已审核预设

继续使用大模型理解同义表达并匹配已发布问题。返回人工审核答案及原有来源，不增加模型生成成本。

### 6.2 第二阶段：知识库

同时检索现有 FAQ 库和资料库。资料库新增《杭电新生指北》快照。

知识片段命中后，模型只能依据命中的杭电或社区片段组织回答，并遵守：

- 开头直接回答用户问题。
- 优先陈述杭电具体情况。
- 不得把其他学校的通例写成杭电事实。
- 每个可核验的具体结论要能追溯到返回来源。
- 证据冲突时明确说明冲突和适用年份。

模型不可用时，仍返回整理后的原始知识片段和来源，不阻塞用户。

### 6.3 第三阶段：杭电优先联网检索

原始问题不再直接作为唯一搜索词。查询构造器至少生成：

1. `杭州电子科技大学 + 用户问题`
2. 对适合校方回答的问题增加 `site:hdu.edu.cn`

结果按以下顺序排序：

1. 杭电官方域名及其子域名；
2. 已批准的新生指北和社区来源；
3. 其他公开网页。

合成提示必须要求模型区分：

- `杭电资料显示`：必须有杭电来源支持；
- `通用建议`：仅在杭电资料不足时补充，并显式标注不是杭电特定政策。

返回继续使用现有批注：

> 该条回复并不在我们的知识库以及 40 个预设问题中，请注意甄别

搜索或模型暂时不可用时，使用确定性兜底回答并照常进入 FIFO 审核队列。

## 7. “社团”反馈的目标行为

输入“给个社团的建议”或“社团有什么作用吗”时，合格结果应当：

- 明确回答杭电存在科技、竞赛、文化体育、志愿公益等类型的社团或学生组织；
- 给出选择建议，例如先参加招新展示、根据时间投入选择 1 至 2 个重点组织、询问真实活动频率；
- 使用杭电官方或已审核社区材料支撑杭电特定陈述；
- 在答案下直接展示可点击的杭电官方链接；
- 不再只输出“请自行寻找团委官网”。

首批可审核的官方候选来源包括：

- `https://www.hdu.edu.cn/news/2025/0610/c7517a279705/page.htm`
  （杭州电子科技大学学生社团科技文化节）
- `https://xxgk.hdu.edu.cn/8797/list.htm`
  （杭州电子科技大学学生管理制度目录）

这些联网材料在进入知识库前仍需走人工审核；实现过程不会因其域名是官方域名就绕过审核队列。

## 8. 管理端改动

在现有内容与审核控制台中补充：

- 指北快照标题、来源、SHA-256、批准时间和 WeKnora 导入状态；
- 待审核回答的来源类型、标题、域名和链接；
- `杭电资料不足`标记，供团队优先补充；
- 审核后的修订答案和来源，沿用现有发布与知识同步边界。

管理员离线不影响回答和排队。原始联网结果不会自动成为已审核知识。

## 9. 组件与边界

- `BrandHeader`：只负责 Logo、品牌文字和副标题。
- `GuideView`：只负责目录、摘要、章节链接和资料声明。
- `SourceList`：统一渲染来源类型、标题和安全链接，供问题卡与回答页复用。
- `useVisualViewport`：封装键盘和视口变化，不处理业务提交。
- `official-search-query`：只负责构造杭电优先查询和来源排序。
- 知识回答合成器：只接收问题、检索片段和来源，不直接访问数据库或搜索网络。
- 指北快照生成与导入：沿用现有批准清单、哈希幂等和 WeKnora 写入流程。

这些单元通过现有 `SourceRef`、知识命中和回答结果接口连接，避免把 UI、检索和审核逻辑写进同一文件。

## 10. 错误处理与安全

- Logo 加载失败时仍显示品牌文字。
- 飞书链接打不开时，目录摘要仍可阅读，并提示稍后重试完整指南。
- 所有外链继续拒绝 `javascript:`、本地地址和其他非 HTTP/HTTPS 协议。
- 模型不得自行生成来源 URL；来源数组只来自知识元数据或搜索结果。
- 官方域名只提升排序和标签，不等于内容永不过时；仍展示标题和适用时间。
- 不记录用户提问正文、访问码、Cookie、TokenDance Key 或 WeKnora Key 到公开日志。
- 不改变 Q11 保持空白、未经审核内容不自动发布等现有红线。

## 11. 测试与验收

### 11.1 自动化测试

- Logo 与品牌名称在问题卡页、指北页和回答页可访问。
- 指北目录、摘要、社区声明和飞书锚点正确。
- 来源按类型显示，安全 URL 可点击，不安全 URL 仅显示文本。
- 视口缩小时提问面板高度随之变化，发送按钮仍在面板可见区域。
- 不支持 `visualViewport` 时回退路径有效。
- 杭电查询构造器添加学校限定词，并优先排序官方域名。
- 知识合成只使用提供的片段和来源；模型失败时仍返回确定性答案。
- 第三阶段批注、FIFO 顺序和管理端隔离保持不变。
- “社团”样例返回杭电特定信息和至少一个安全来源，而不是泛大学模板。

### 11.2 浏览器验收

- 375×667 和 390×844 两种手机视口。
- 用户端首页、指北页、提问弹窗、回答页和本地管理端。
- 键盘模拟前后的输入框与发送按钮位置。
- 公网测试入口只开放用户页面，管理接口继续返回 404。

### 11.3 实机边界

桌面浏览器和移动设备模拟不能完全等价于微信内置浏览器软键盘。自动化验收通过后，还需在至少一台 iPhone 和一台安卓手机的微信内置浏览器中完成：打开提问、输入多行文字、滚动、发送和关闭键盘。若当前没有相应设备，应明确记录为待实机验证，不能宣称已经完成微信键盘兼容验收。

## 12. 本次范围之外

- 不把飞书替换成新的内容管理系统。
- 不自动同步飞书的每次修改。
- 不开放公网管理端。
- 不改变现有访问码和公网网关安全策略。
- 不在本轮迁移到云服务器或申请域名、ICP 备案。
- 不自动审核或发布新生原始反馈。
