# 2026 新生 40 问征集与语义识别设计

日期：2026-07-21

## 目标

首批建立 40 个本科新生高频“问题意图”，向 40-50 人团队征集学长学姐的真实回答。40 是首批内容规模，不是程序上限；后续可增加、合并、停用问题而不改路由代码。

## 内容征集

每个问题包含：编号、稳定意图 ID、标准问题、典型问法、需要回答的要点。团队成员按熟悉程度认领，不要求一人回答全部问题。

每份回复必须尽量标注：回答者年级/专业、适用校区、经历发生时间、个人经验或官方事实、官方链接/截图、仍不确定的部分。政策、费用、时间、名额、升学比例等事实不得只凭印象写成确定结论。

收回的 Markdown 和截图由 Codex 执行 OCR、按问题归档、去重、识别冲突、区分共同结论与个体体验，再形成候选标准答案。候选答案经负责人审核后才能把状态从 `collecting` 改为 `approved`。

## 数据模型

```json
{
  "id": "campus-card-issue",
  "question": "校园卡如何领取、激活和使用？",
  "intentDescription": "询问新生校园卡或一卡通的领取、激活、充值和首次使用，不包含丢失挂失。",
  "aliases": ["学校怎么办校园卡", "一卡通去哪里领", "饭卡怎么激活"],
  "keywords": ["校园卡", "一卡通", "饭卡"],
  "intentKeywords": ["领取", "办理", "激活", "充值"],
  "answerStatus": "collecting",
  "answer": "",
  "sources": []
}
```

意图 ID 是稳定标识；标准问题文字可以调整。新增第 41 个问题只增加数据，不改程序。

## 识别流程

1. 标准化用户问题，使用标准问题、典型问法、关键词与意图关键词进行本地匹配。
2. 本地高置信度命中且答案状态为 `approved` 时直接回复。
3. 本地未确定时，把用户问题和当前启用的意图 ID/说明发送给 DeepSeek V4，要求只返回 JSON：`intentId`、`confidence`、`reason`。
4. 模型置信度达到阈值且该意图已有审核答案时，按默认问题回复。
5. 否则继续知识库，再进入联网兜底和审核队列。

大模型只负责“它在问哪类问题”，不自行改写预设答案。DeepSeek 不可用时仍可依靠本地典型问法匹配，不阻塞系统。

## 当前答案处理

现有 10 条演示答案统一视为 `draft-unverified`，不作为正式默认回答。新 40 问初始状态全部为 `collecting`。在团队答案完成审核前，本地产品显示“团队答案征集中”，避免继续传播简陋或错误内容。

## 本阶段不做

本阶段不导入完整飞书知识库、不执行公网部署、不自动发布未经审核的团队回复。先完成 40 问征集、语义意图结构和回收模板。
