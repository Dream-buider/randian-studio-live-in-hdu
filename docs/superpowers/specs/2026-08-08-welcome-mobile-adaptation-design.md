# LIVE IN HDU 初始化页移动端自适应设计

## 1. 背景与问题证据

初始化页在本地开发地址上能够呈现完整的校园晨曦背景、专用标题字体、流星与镜头圆环效果，但通过公网内测网关在手机上访问时出现了明显退化。

当前排查结果表明，异常由两个层面共同造成：

1. 公网网关只显式放行了 Logo 与构建目录中的 `/assets/*`，没有放行初始化页使用的 `/brand/campus-dawn-welcome.webp` 和 `/fonts/hdu-arrival-display.woff2`。实测这两个公网请求均返回 404，而本地开发地址返回 200。因此手机端只能显示备用底色和系统字体。
2. 页面使用 `auto minmax(0, 1fr) auto auto` 组织主要区域，并在页脚中加入较大的视口高度间距。屏幕比例变化时，空白区域会优先拉伸，标题、倒计时与页脚之间的视觉比例不稳定。

正常视觉基准以用户确认的第二张截图为准。

## 2. 目标

- 公网和本地加载同一套背景图、字体、Logo 与动画资源。
- 使用用户提供的 `7d36a1c3cef23acef0cda0cba338a974.png` 替换现有燃点工作室 Logo；不调用生成模型重绘。
- 在常见手机宽度和高度下保持与视觉基准接近的纵向构图。
- 品牌位于顶部，标题与倒计时作为一个整体位于主视觉区域，日期与入口按钮稳定停留在底部安全区域上方。
- 短屏压缩间距和字号，长屏限制空白增长；不得出现横向滚动、内容被裁掉或按钮落入系统安全区。
- 保留现有视觉语言，不重新设计流星、圆环、倒计时卡片、颜色或背景画面。
- 保持公网内测网关的封闭边界，不开放管理端，也不允许任意文件读取。

## 3. 非目标

- 不调整倒计时业务逻辑和开学日期。
- 不修改问题页、聊天页、指南页或管理端。
- 除用户本轮指定的新 Logo 外，不改动其他品牌图形、校园背景图、字体和流星算法。
- 不处理云服务器、域名或正式生产部署。
- 不让未登录用户直接访问页面资源。

## 4. 采用方案

采用“资源安全放行 + 三段式响应布局”。

### 4.1 公网资源边界

在公网内测网关中建立声明式静态资源映射，仅登记当前客户端需要的公开资源：

- `/brand/randian-studio-logo.png`
- `/brand/campus-dawn-welcome.webp`
- `/fonts/hdu-arrival-display.woff2`
- `/favicon.svg`

每条资源路由继续经过现有浏览器会话校验。映射值只能指向构建输出目录中的固定相对路径，不接受用户输入的磁盘路径，也不开放通配的 `/brand/*` 或 `/fonts/*`。新增公开资源时必须显式加入映射和测试。

新 Logo 沿用 `/brand/randian-studio-logo.png` 这一稳定路径，用用户提供的 PNG 原图覆盖现有文件。这样初始化页、问题页、聊天页和指南页无需分别修改引用，也不会形成新旧 Logo 并存。

网关应为 WebP、WOFF2、PNG 和 SVG 返回正确的 `Content-Type`。不存在的品牌资源、字体资源、路径穿越、管理端路径和未知路径继续返回 404。

### 4.2 页面结构

初始化页改为三个职责明确的视觉区域：

1. `welcome-brand`：顶部品牌区，包含 Logo、LIVE IN HDU 和信号状态。
2. `welcome-stage`：主视觉区，将引导标题和四张倒计时卡片组合在同一个容器中，内部间距受控，不再被剩余高度拆散。
3. `welcome-footer`：底部操作区，包含北京时间和“进入新生问答”按钮，并吸收底部安全区。

背景、流星、镜头圆环和曝光线继续使用绝对定位，仅作为装饰层，不参与内容高度计算。

### 4.3 响应式规则

- 页面使用 `100svh` 作为稳定基础高度，并用 `100dvh` 响应移动浏览器地址栏变化。
- 主体采用 `auto minmax(0, 1fr) auto` 三行网格；中间行负责安置整个 `welcome-stage`，不让标题和倒计时彼此漂移。
- `welcome-stage` 使用 `clamp()` 控制标题字号、卡片高度、卡片间距和区块间距。
- 宽度不超过 350px 时缩小左右安全边距、卡片间隔和品牌尺寸，但四张卡片仍保持单行。
- 高度不超过 760px 时压缩标题、倒计时卡片和底部操作区之间的距离。
- 高屏设备限制中间主视觉区的最大空白，不随着视口无限拉伸。
- 所有水平尺寸均受容器宽度约束，页面根节点不得产生横向滚动。
- 背景继续使用 `cover`，允许在不同宽高比上裁切左右或上下边缘，以优先填满屏幕并保持主体校园画面位于底部。
- 顶部和底部均保留 `env(safe-area-inset-*)`，适配刘海、灵动岛和手势区域。

### 4.4 动画与性能

- 保留现有 WebGL 流星、曝光线、圆环和入场动画。
- 继续遵守 `prefers-reduced-motion`；减少动态效果的用户不运行入场动画和持续扫光。
- WebGL 画布保持低功耗偏好和设备像素比上限，不因响应布局提高渲染负载。
- 背景加载失败时仍保留现有备用底色，页面和入口按钮必须可用。

## 5. 数据与请求流程

1. 用户通过公网地址登录内测网关。
2. 网关签发已有的安全会话 Cookie。
3. 浏览器请求初始化页 HTML、构建后的 CSS/JS、Logo、背景图和字体。
4. 网关逐项校验会话，并只从声明式映射或受限 `/assets/*` 目录返回文件。
5. Vue 页面加载后计算倒计时；布局完全由客户端视口和 CSS 响应规则决定，不新增后端接口。
6. 用户点击入口后进入现有问题卡片页面。

## 6. 错误处理与安全

- 未登录的页面和静态资源请求继续跳转登录页或被拒绝。
- 映射资源在构建输出中缺失时返回 404，不暴露本地文件路径或错误堆栈。
- 资源路径不得包含 `.`、`..`、空字节或绝对路径。
- `/admin`、管理 API、健康检查和未知路由保持现有 404 行为。
- 本次修改不得改变邀请码、会话期限、限流或上游 API 代理规则。

## 7. 测试方案

### 7.1 自动化测试

- 网关测试覆盖登录后 GET/HEAD 背景图和字体，断言状态码、内容类型与非空文件内容。
- 网关测试继续覆盖未登录访问、未知品牌/字体资源、路径穿越和管理端路径。
- 初始化页组件测试断言三段式结构存在，标题与倒计时处于同一主视觉容器。
- 既有倒计时、流星、公开试用、安全边界和其他前端测试必须全部通过。

### 7.2 构建与真实视口验收

重新构建公网内测客户端和网关后，至少检查以下 CSS 视口：

- 320 × 568：窄且短。
- 360 × 800：常见安卓尺寸。
- 390 × 844：常见全面屏尺寸。
- 430 × 932：宽且高。

每个尺寸均检查：背景图可见、专用字体生效、品牌完整、标题与倒计时比例接近基准、四张卡片不换行、日期和按钮可见、底部不被遮挡、无横向滚动。

公网最终验收还需确认背景图与字体返回 200，并在真实手机上关闭旧页面后重新打开，以排除旧缓存。

## 8. 验收标准

- 公网手机页面与正常基准具有相同的背景、字体和主要构图。
- 初始化页、问题页、聊天页和指南页均通过原有稳定资源路径显示用户提供的新 Logo。
- 320 至 430px 宽的目标视口均无横向溢出。
- 568 至 932px 高的目标视口均能看到核心倒计时与可点击入口；短屏允许压缩，高屏不出现异常大空洞。
- 背景裁切可以随屏幕比例变化，但校园天际线和底部暖色区域仍参与整体画面。
- 公网网关没有新增任意目录读取能力，管理端继续不可访问。
- 自动化测试、公开试用构建和公网资源检查全部通过。
