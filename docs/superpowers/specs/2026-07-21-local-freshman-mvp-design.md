# LIVE IN HDU 本地新生问答 MVP 设计

日期：2026-07-21

## 目标与验收

今天交付一个无需 Docker、直接在当前 Windows 电脑运行的本地雏形。电脑访问管理端，手机在同一局域网通过电脑 IP 访问问答端。

验收必须覆盖：

1. 预设问题命中后直接返回。
2. 未命中预设、但命中本地知识库后直接返回并显示来源。
3. 两者均未命中时仍返回答案，逐字显示风险批注，并自动进入审核队列。
4. 审核队列按创建时间和序号从上到下排列，显示“第 N 个未收录”和“待审核”。
5. 管理端能够修改答案、通过或驳回；通过后的答案自动加入本地知识库，下一次同类问题可命中。
6. 关闭服务再启动后，审核数据仍存在。

## 今天版技术方案

采用 Node.js 24 内置 HTTP、文件和测试模块，不新增运行时依赖。数据存储为本地 JSON 文件，写入时先生成临时文件再原子替换，适合单机演示；正式部署再迁移 PostgreSQL。

前端是响应式原生 HTML/CSS/JavaScript，包含：

- `/`：手机问答页。
- `/admin`：审核后台。
- `/api/health`：运行状态。
- `/api/ask`：三段问答。
- `/api/reviews`：审核列表。
- `/api/reviews/:id`：审核操作。

## 三段路由

- 第一段：读取 `data/presets.json`，按标准化文本、关键词和相似度判断。
- 第二段：读取 `data/knowledge.json`，按标题、关键词和正文评分，超过配置阈值后返回。
- 第三段：如果配置了 DeepSeek Key，则先获得 Web Search 摘要，再调用 `deepseek-v4-flash`；未配置密钥时使用明确标记的演示回答，使完整业务流程仍可验收。

第三段始终追加：

`该条回复并不在我们的知识库以及 40 个预设问题中，请注意甄别`

模型名、阈值、端口、密钥和批注从环境变量读取，业务代码不写死凭证。

## 数据与审核

审核记录包含：ID、单调递增序号、问题、模型答案、来源、创建时间、状态、最终答案和审核时间。第三段先持久化记录，再把答案返回用户；管理员是否在线不参与问答流程。

通过审核时，将最终问题和答案以新条目写入 `knowledge.json`。驳回记录不删除，以保留审计轨迹。

## 错误处理

- 问题为空返回 400。
- DeepSeek 或搜索超时后使用演示/降级回答，并保留固定批注和审核记录。
- JSON 文件损坏时拒绝覆盖原文件，并把错误写入服务日志。
- 静态文件路径经过根目录限制，防止读取项目中其他文件。
- 管理端今天仅限本机/局域网演示，正式公网部署前必须增加登录鉴权。

## 非目标

今天不完成飞书自动同步、微信小程序送审、多人权限、PostgreSQL、完整 WeKnora 容器联调或公网部署。这些能力不影响本地雏形验收。
