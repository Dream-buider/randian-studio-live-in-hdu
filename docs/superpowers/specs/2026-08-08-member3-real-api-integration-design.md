# 成员 3 最终前端与真实 API 融合设计

## 目标

把成员 3 提交 `d149672` 中、当前在 `http://127.0.0.1:5174/` 展示的用户端最终视觉，融合到本机最新真实业务基线 `7b705d3`。最终正式模式必须继续请求本机 `3210` 的真实 API、数据库、WeKnora、TokenDance 与审核队列，不得把 UI Preview 的模拟问答带入正式构建。

## 已确认产品决策

- 保留成员 3 当前原版的初始化页与流星效果，不实施单向流星或 28 条流星改造。
- `/` 为初始化页；`/questions` 为问题卡；`/guide` 为新生指北；`/chat` 为真实问答结果；`/admin` 仍为本地管理端。
- 学生端使用成员 3 的暖色电影感视觉、倒计时、流星、问题卡和指北信号站。
- 管理端业务与样式边界不变，不把学生端装饰带进管理端。
- 正式模式失败时显示失败状态，不静默回退到模拟数据。

## 架构与数据流

1. `WelcomeView` 只负责初始化视觉、倒计时和进入 `/questions`。
2. `QuestionDeckView` 通过 `GET /api/questions` 读取已审核真实问题。
3. `ChatView` 通过 `POST /api/ask` 获取预设、知识库或联网搜索回答，并保留来源和甄别批注。
4. Vite 开发服务器只代理严格匹配 `/api` 或 `/api/...` 的请求到 `http://localhost:3210`。
5. `ui-preview` 模式可以继续给远端前端开发使用模拟数据，但模拟内容通过动态导入隔离，并由生产构建门禁扫描阻止泄漏。

## 融合边界

- 从成员 3 最终提交移植用户端 Vue、CSS、字体、图片、OGL 流星组件与相关 Web 测试。
- 保留本机 `web/api.ts` 已有的最新数据结构、来源校验、审核字段和真实接口，仅叠加 UI Preview 选择层。
- 不修改后端业务、数据库迁移、私密配置、API 密钥或 D 盘运行时数据；只允许在本地与公开体验网关的 SPA 白名单中补充新增的 `/questions` 路由。
- 不覆盖已有的杭电来源、指南内容、软键盘修复和公开体验安全逻辑。

## 错误与安全处理

- 真实 API 请求失败时保持问题列表/回答页的显式重试状态。
- 回答与来源继续按纯文本渲染；来源链接继续只允许 HTTP/HTTPS。
- 正式构建和公开体验构建必须执行模拟数据标记扫描。
- `prefers-reduced-motion`、WebGL 失败降级、页面隐藏暂停和组件卸载清理继续保留。

## 验收标准

- 当前 5174 原版初始化页的结构与视觉完整进入真实融合分支。
- 正式开发模式访问 `/api/questions` 和 `/api/ask`，不使用 mock。
- `npm run test:web`、`npm run test:all`、`npm run build`、`npm --prefix apps/freshman-mvp run build:trial` 全部通过。
- 正式产物与公开体验产物均不含 UI Preview 模拟问题或模拟回答标记。
- 本机真实后端和融合前端启动后，初始化页、真实问题卡、真实提问、指北与本地管理端可访问，且直接刷新 `/questions` 返回前端应用而不是 404。
