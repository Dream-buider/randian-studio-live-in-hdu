# 《杭电新生指北》问答检索与链接设计

日期：2026-08-10

## 1. 目标

让 LIVE IN HDU 的聊天问答优先利用团队拥有版权且已经人工批准的《杭电新生指北》。当用户问题与指北内容相关时，系统先给出基于指北片段的总结，再展示最多三个可点击的飞书原文章节链接。只有预设答案和指北都未命中时，才进入现有联网检索与人工审核队列。

本设计不引入管理员账号体系，不部署 WeKnora，不改变现有审核队列结构，也不把完整指北正文提交到公开 GitHub。

## 2. 已确认的产品规则

1. 链接指向飞书原文，而不是站内 `/guide` 页面。
2. 一个回答最多展示三个相关链接。
3. 已审核预设答案的优先级高于模型总结，模型不得覆盖人工答案。
4. 第一版链接落到所属大章节；链接名称仍精确到命中的具体小节。
5. 未命中预设但命中指北时，回答属于知识库回答，不显示联网未核验批注，也不进入待审核队列。
6. 指北未命中时，继续使用当前 SearXNG、DeepSeek 和人工审核流程。

## 3. 方案选择

采用云端轻量《杭电新生指北》专用检索层，不在当前 2 核 4 GB 云服务器上额外部署 WeKnora。

理由：

- 当前云端 `KNOWLEDGE_PROVIDER=local`，只读取小型本地知识文件，完整指北并未进入实际检索链路。
- 指北文档规模有限，可以在启动时切分并建立内存索引，无需新增数据库或容器。
- DeepSeek 只参与候选片段重排与受约束总结；即使模型不可用，系统仍能返回确定性摘要与链接。
- 该方案资源占用低、故障面小，并保留以后替换成 WeKnora 或其他向量检索引擎的接口边界。

## 4. 资料存储与版本

### 4.1 私有资料文件

完整指北使用已经批准的 Markdown 快照：

`hdu-freshman-guide-2026.md`

本地批准源继续保存在 D 盘运行目录；云端副本存放在应用目录以外的私有资料目录，并通过环境变量 `FRESHMAN_GUIDE_PATH` 指定。文件不得进入公开 Git、前端构建产物或客户端 API 原文响应。

### 4.2 可公开的索引元数据

代码内只保存：

- 大章节标识和名称；
- 经过人工确认的飞书大章节深链；
- 常见别称、简称和错别字映射；
- 解析规则和版本号。

第一版可靠深链覆盖：开学准备篇、宿舍篇、生活与地图篇、教学区与校园设施篇。未配置章节深链的小节回退到《杭电新生指北》根页面，不能生成不存在的锚点。

## 5. 文档解析与切分

新增独立的指北文档加载器，在应用启动时完成以下操作：

1. 读取并验证 UTF-8 Markdown 文件。
2. 忽略文档元数据、分隔线和“原文图片未转录”等占位提示。
3. 按三级、四级和五级标题切分内容，并保留完整标题路径。
4. 每个片段记录：片段 ID、标题路径、正文、所属大章节、展示标题、飞书链接和顺序。
5. 过长片段按自然段继续切分，保持标题上下文；过短的连续片段可合并。
6. 任何解析错误不得阻止主服务启动；健康状态记录为降级，并停用指北检索。

该加载器只负责结构化文档，不负责判断用户问题。

## 6. 相关性判断

新增独立的指北检索器，采用两阶段策略。

### 6.1 确定性候选召回

对问题进行 NFKC 归一化、空白与标点清理，并应用别称表。例如：

- `航电钉`、`杭电钉`、`学校钉钉`、`钉钉认证` → 钉钉杭州电子科技大学认证；
- `学号怎么查`、`班级号在哪看` → 学号班级号获取；
- `寝室多大`、`宿舍大小`、`几人间` → 宿舍类型与环境。

候选评分综合标题命中、别称命中、关键词覆盖和正文词项命中。`学校`、`大学`、`怎么办` 等泛化词不单独构成命中。检索器最多交给模型八个候选片段。

### 6.2 DeepSeek 受约束重排与总结

DeepSeek 接收用户问题和候选片段 ID、标题、正文，只能：

- 选择与问题直接相关的片段；
- 根据所选片段生成简洁中文总结；
- 返回使用过的片段 ID。

模型不得引用候选之外的杭电事实、网址或政策。服务端只接受候选集合内的片段 ID，并根据服务端元数据生成来源链接，不能采用模型生成的 URL。

若模型返回空答案、未知片段 ID、拒答或请求失败，使用确定性候选的关键句作为摘要，不跳过已找到的指北内容。

## 7. 问答路由

### 7.1 命中已审核预设问题

1. 返回现有人工审核完整答案，内容和版本不变。
2. 同时执行指北检索。
3. 若命中，在正文后增加独立的“《杭电新生指北》补充”段落，并合并最多三个指北来源。
4. 指北总结不能删除、改写或覆盖人工答案。
5. 指北未命中或不可用时，仍正常返回原预设答案。

### 7.2 未命中预设但命中指北

1. 返回指北总结。
2. 路由标记保持为 `knowledge`，可信状态为知识库来源。
3. 返回最多三个去重后的指北来源。
4. 不显示联网未核验批注。
5. 不创建新的人工审核任务。

### 7.3 指北未命中

保持当前流程：查询其他本地知识记录；仍未命中时调用 SearXNG 和 DeepSeek，返回未核验批注，并把问题加入 FIFO 人工审核队列。

## 8. 来源链接与前端呈现

后端继续返回现有 `SourceRef` 结构，避免扩大客户端协议。指北来源示例：

```json
{
  "type": "community",
  "title": "杭电新生指北 · 钉钉杭电认证",
  "url": "已批准的飞书开学准备篇深链",
  "updatedAt": "2026-07-30"
}
```

前端复用现有安全链接组件：

- 标签显示为“新生指北”；
- 标题显示具体小节名称；
- 点击后以新页面打开飞书；
- 只允许 `http:` 和 `https:`；
- 对相同 URL 与标题组合去重；
- 最多显示三个指北来源。

第一版不改变聊天气泡结构，不增加新的弹窗或嵌入式飞书页面。

## 9. 故障与安全边界

1. 指北文件缺失、不可读或解析失败：停用指北检索，保留现有预设、知识库和联网流程。
2. DeepSeek 失败：返回确定性指北摘要和链接。
3. 指北命中但链接未配置：使用飞书根页面，不伪造锚点。
4. 指北未命中：不能为了强行引用指北而返回无关内容。
5. 模型生成的链接一律不采用。
6. 指北正文不在 API 中整篇返回，不写入日志，不提交到公开 Git。
7. 部署前备份云端代码、环境配置和 SQLite 数据库；失败时恢复原构建和数据库。
8. 本功能不得改变现有公网管理接口 403 边界。

## 10. 维护方式

第一版采用人工批准文件替换：

1. 团队导出新版 Markdown。
2. 人工对比、确认版权与内容。
3. 备份当前云端指北文件。
4. 上传新文件并更新版本日期。
5. 重启服务，运行固定问题集验收。

管理端上传、版本审核和热更新属于后续独立需求，本轮不实现。

## 11. 测试与验收

### 11.1 单元测试

- Markdown 标题切分、长片段拆分与占位提示过滤；
- 大章节与深链映射；
- 别称、简称和错别字归一化；
- 相关候选排序与泛化问题拒绝；
- 模型返回未知片段 ID 时回退；
- 来源去重与最多三个限制；
- 文件缺失和解析失败不阻塞启动。

### 11.2 路由测试

- 预设命中时人工答案保持不变，并可增加指北补充和链接；
- 仅指北命中时返回 `knowledge`，不进入审核队列；
- 指北未命中时继续走联网搜索并进入审核队列；
- DeepSeek 不可用时仍返回指北确定性摘要；
- 公网管理接口继续返回 403。

### 11.3 固定验收问题

- 学号在哪里查？
- 航电钉怎么注册？
- 学校钉钉怎么认证？
- 杭电宿舍有多大？
- 宿舍是几人间？
- 学号查到以后怎么注册杭电钉？
- 一个与指北无关的问题。

### 11.4 云端验收标准

- 客户端与管理端页面继续返回 200；
- 公网 `/api/reviews` 继续返回 403；
- 以上相关问题返回指北总结和可点击飞书链接；
- 无关问题不附带指北链接；
- 23 个既有问题及现有审核队列数量在部署前后保持一致；
- 不使用真实待审核任务做自动验收；
- 生产数据库副本上的完整路由测试通过后，才允许切换云端构建。
