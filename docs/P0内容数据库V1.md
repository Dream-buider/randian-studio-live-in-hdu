# HDU Feishu Community OS P0 内容数据库 V1

适用范围：LIVE IN HDU 飞书知识库 V1 阶段的 5 个核心内容库。

落地方式：每一类内容建一个飞书多维表格；每条记录审核通过后，再链接到知识库页面或资料附件。普通同学通过飞书表单投稿，维护者在多维表格里审核、补源、发布。

通用状态字段：

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| 待审核 | 投稿刚进入数据库 | 审核人核验来源、补字段 |
| 待补充 | 信息方向可用，但缺关键字段 | 退回贡献者补充 |
| 已发布 | 已通过审核并可在知识库展示 | 定期复查 |
| 需复核 | 时间敏感或收到纠错 | 暂不推荐置顶 |
| 已下架 | 侵权、过期、无法核实或不适合公开 | 保留后台记录，不前台展示 |

通用可靠等级：

| 等级 | 使用条件 |
| --- | --- |
| A | 学校/学院/教务处/研究生院/官方平台公开文件，或任课教师/辅导员明确授权的信息 |
| B | 至少 2 名不同来源同学独立验证，且能提供截图、原文件、课程群通知等证据 |
| C | 单人经验或个人整理，必须标注“仅供参考” |

通用禁止项：

- 不公开身份证号、学号、手机号、宿舍号、私人微信、私人 QQ、未公开邮箱等个人隐私。
- 不发布盗版教材、付费课程资源、未授权题库、含水印的商业资料。
- 不发布辱骂、排名羞辱、人身攻击、未经核实的教师评价或实验室评价。
- 所有政策类信息必须有来源、发布日期和最后复核日期。

## 1. 课程数据库

用途：让学生能按课程名、学院、年级、学期搜索“这门课是什么、怎么考、怎么学、有哪些资料入口”。

### 数据库字段

| 字段名 | 类型 | 必填 | 填写说明 |
| --- | --- | --- | --- |
| 课程名称 | 文本 | 是 | 使用教务系统或培养方案里的正式名称，如“高等数学 A（一）” |
| 课程别名 | 多行文本 | 否 | 学生常用叫法，如“高数 A1”“大物”“程设” |
| 课程代码 | 文本 | 否 | 以教务系统/培养方案为准；没有就留空，不猜 |
| 课程类别 | 单选 | 是 | 公共基础课/专业基础课/专业课/通识课/体育课/实验课/实践环节/其他 |
| 开课学院 | 单选 | 否 | 按培养方案或课程归属填写 |
| 适用学院/专业 | 多选 | 是 | 可填“全校”“计算机学院”“自动化学院”等 |
| 适用年级 | 多选 | 是 | 大一/大二/大三/大四/研究生/不固定 |
| 常见开课学期 | 多选 | 是 | 大一上/大一下/大二上/大二下/不固定 |
| 学分 | 数字 | 否 | 以培养方案为准 |
| 课程性质 | 单选 | 否 | 必修/限选/任选/不确定 |
| 考核方式 | 多选 | 是 | 闭卷考试/开卷考试/论文/大作业/实验报告/机考/课堂展示/平时作业/不确定 |
| 成绩构成 | 多行文本 | 否 | 只写有来源的信息，如“平时 30% + 期末 70%”；不确定写“不同老师可能不同” |
| 教材/参考书 | 多行文本 | 否 | 写书名、版本、作者；不能确认就留空 |
| 先修要求 | 多行文本 | 否 | 如“需要掌握 C 语言基础”“建议先学线性代数” |
| 学习建议 | 多行文本 | 否 | 只写可操作建议，不写情绪化评价 |
| 常见坑 | 多行文本 | 否 | 如“实验报告截止时间早于理论课考试周” |
| 资料入口 | 关联记录 | 否 | 关联“历年卷数据库”或课程资料页 |
| 来源材料 | 附件/链接 | 是 | 教务系统截图、培养方案 PDF、课程群通知、教师课件授权说明等 |
| 可靠等级 | 单选 | 是 | A/B/C |
| 审核状态 | 单选 | 是 | 待审核/待补充/已发布/需复核/已下架 |
| 最后复核日期 | 日期 | 是 | 每学期至少复核一次高频课程 |
| 贡献者 | 人员/文本 | 是 | 可匿名展示，但后台需保留提交人 |
| 审核人 | 人员 | 否 | 发布前填写 |
| 知识库页面链接 | URL | 否 | 发布后填对应文档链接 |

### 填写说明

- 课程名称、学分、课程性质优先来自培养方案或教务系统。
- 考核方式和成绩构成只接受课程群通知、教学大纲、任课教师说明、已修同学截图；单人口述只能标 C。
- 教师相关内容只记录“教学安排事实”，不做“好/差/水/坑”等主观标签。
- 如果同一课程不同学院、不同老师差异明显，拆成“课程主记录 + 经验子记录”，不要把所有信息混在一条里。

### 内容审核标准

通过条件：

- 课程名称、适用对象、开课学期至少能被一个来源证明。
- 成绩构成、考试形式若无来源，必须写“不确定/不同老师可能不同”。
- 学习建议具体可执行，如“按章节整理错题”“实验课提前配置环境”。

退回条件：

- 只有“这课很水/很难/老师很坑”等情绪评价。
- 使用无法核验的排名、挂科率、给分传言。
- 上传整套未授权课件、教材扫描件或商业题库。

### 贡献者填写表单格式

表单标题：提交课程信息

字段：

- 课程名称：短文本，必填
- 课程别名：短文本，选填
- 你的学院/专业/年级：短文本，必填，后台使用
- 这门课适合哪些同学：多选，必填
- 常见开课学期：多选，必填
- 考核方式：多选，必填，可选“不确定”
- 成绩构成：长文本，选填
- 教材/参考书：长文本，选填
- 你认为最有用的学习建议：长文本，必填
- 常见坑或注意事项：长文本，选填
- 信息来源：多选，必填；教务系统/培养方案/课程群通知/任课教师说明/个人经验/其他
- 上传证明材料：附件，至少 1 个；可打码
- 是否允许公开署名：单选；公开昵称/匿名/仅后台可见

## 2. 历年卷数据库

用途：按课程、年份、考试类型沉淀可公开、可授权、可检索的复习资料入口。

### 数据库字段

| 字段名 | 类型 | 必填 | 填写说明 |
| --- | --- | --- | --- |
| 资料标题 | 文本 | 是 | 格式：课程名 + 年份 + 学期 + 考试类型，如“高等数学 A（一）2024-2025 学年第一学期期末回忆版” |
| 关联课程 | 关联记录 | 是 | 关联课程数据库 |
| 年份/学年 | 文本 | 是 | 如“2024-2025” |
| 学期 | 单选 | 是 | 第一学期/第二学期/短学期/不确定 |
| 考试类型 | 单选 | 是 | 期中/期末/补考/重修/模拟/回忆版/题型整理/其他 |
| 资料类型 | 单选 | 是 | 原卷授权版/回忆版/题型整理/答案解析/复习提纲/实验题/其他 |
| 文件附件 | 附件 | 否 | 只上传允许公开的文件 |
| 外部链接 | URL | 否 | 可指向学校公开页面、贡献者授权网盘、知识库文档 |
| 是否含答案 | 单选 | 是 | 有完整答案/有部分答案/无答案/不确定 |
| 答案来源 | 单选 | 否 | 任课教师公开/助教公开/学生整理/未知 |
| 清晰度 | 单选 | 否 | 高清/可读/较模糊/需重扫 |
| 授权状态 | 单选 | 是 | 原创授权/公开来源/教师授权/仅回忆整理/无法确认 |
| 敏感信息处理 | 复选 | 是 | 已去除姓名/学号/班级/水印/无敏感信息 |
| 适用说明 | 多行文本 | 是 | 说明适用课程、年份差异、是否仅供参考 |
| 来源材料 | 附件/链接 | 是 | 投稿截图、授权说明、公开来源链接等 |
| 可靠等级 | 单选 | 是 | A/B/C |
| 审核状态 | 单选 | 是 | 待审核/待补充/已发布/需复核/已下架 |
| 最后复核日期 | 日期 | 是 | 资料首次发布和每次纠错后更新 |
| 贡献者 | 人员/文本 | 是 | 可匿名 |
| 审核人 | 人员 | 否 | 发布前填写 |

### 填写说明

- “原卷”只有在确认公开或授权后才可上传；不能确认时改做“回忆版/题型整理”。
- 文件中出现姓名、学号、班级、成绩、水印、私聊记录，必须打码后再入库。
- 答案解析必须标明来源；学生整理答案要允许评论纠错。
- 同一课程同一年份可有多条记录，但标题必须能区分“原卷授权版/回忆版/答案解析”。

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

### 内容审核标准

通过条件：

- 资料类型、课程、年份、考试类型明确。
- 授权状态清楚；无法确认版权的资料不作为附件公开。
- 文件可打开、可读、已去敏感信息。

退回条件：

- 资料来源是付费题库、盗版教材扫描、网课讲义搬运。
- 含学生个人信息或教师未公开批注。
- 标题夸大，如“必考原题”“内部答案”“包过资料”。

### 贡献者填写表单格式

表单标题：提交历年卷/复习资料

字段：

- 资料对应课程：短文本，必填
- 资料标题：短文本，必填
- 学年：短文本，必填
- 学期：单选，必填
- 考试类型：单选，必填
- 资料类型：单选，必填
- 是否包含答案：单选，必填
- 资料来源和授权情况：长文本，必填
- 上传资料：附件，选填；不能上传未授权资料
- 外部公开链接：URL，选填
- 是否已去除姓名/学号/水印：复选，必填
- 适用说明和风险提示：长文本，必填
- 是否允许公开署名：单选，必填

## 3. 实验室数据库

用途：给本科生和低年级研究生提供“公开、克制、可核验”的实验室入口信息，帮助了解方向、要求和联系渠道。

### 数据库字段

| 字段名 | 类型 | 必填 | 填写说明 |
| --- | --- | --- | --- |
| 实验室/团队名称 | 文本 | 是 | 使用官网公开名称 |
| 所属学院/平台 | 单选/文本 | 是 | 如计算机学院、电子信息学院、校级平台等 |
| 负责人/PI | 文本 | 否 | 只填写官网公开信息 |
| 研究方向标签 | 多选 | 是 | 机器学习/计算机视觉/嵌入式/射频电路/脑机接口/数据挖掘/机器人/其他 |
| 简介 | 多行文本 | 是 | 100-300 字，只写公开事实 |
| 官网/公开页面 | URL | 是 | 必须有公开来源；没有公开来源不发布 |
| 公开联系方式 | 文本 | 否 | 只填官网公开邮箱、办公室电话或招生页面链接 |
| 招收对象 | 多选 | 否 | 本科生科研训练/大创/毕设/硕士/博士/不确定 |
| 加入方式 | 多行文本 | 否 | 如“阅读官网招生说明后邮件联系”；不能写私人内推链路 |
| 推荐准备 | 多行文本 | 否 | 如“准备简历、成绩单、项目经历、GitHub/论文阅读记录” |
| 常用技能 | 多选 | 否 | Python/C/C++/Matlab/Verilog/Linux/PyTorch/硬件调试/论文阅读/其他 |

| 风险提示 | 多行文本 | 否 | 如“不同导师要求不同，以正式沟通为准” |
| 来源材料 | 附件/链接 | 是 | 官网、学院页面、招生简章、实验室公众号公开文章 |

| 审核状态 | 单选 | 是 | 待审核/待补充/已发布/需复核/已下架 |

| 贡献者 | 人员/文本 | 是 | 可匿名 |
| 审核人 | 人员 | 否 | 发布前填写 |

### 填写说明

- 实验室数据库只收录“公开可核验信息 + 审核过的经验”，不做黑榜、红榜或打分榜。
- 招生名额、补贴、工位、组会频率等易变信息，只有公开页面或团队成员明确授权才可发布。

- 对实验室氛围的描述必须改写为可验证事实或匿名经验，并标注 C 级。

### 内容审核标准

## 4. 新生生存指南

用途：沉淀新生从录取后到开学前后最常遇到的问题，按事项而不是按长文散落管理。

### 数据库字段

### 填写说明

- 每条只解决一个问题；例如“快递地址”单独一条，“取件地点”单独一条。
- 新生指南的日期、费用、报到地点每年都可能变，必须有“适用年份”和“最后复核日期”。
- 对“买什么”类内容，分成“必须带”“建议带”“到校后再买”，避免制造焦虑。
- 所有官方流程都要给出官方来源入口，不能只写“听说”。

### 内容审核标准

通过条件：

- 有官方来源或明确标注为经验建议。
- 步骤能照着执行，不出现“自己看情况”式空话。
- 对每年变化的信息加“以当年通知为准”并设置复核日期。

退回条件：

- 给出未经核实的具体报到日期、收费标准、地址。
- 宣传商家、代购、租赁、电话卡、宽带套餐。
- 制造焦虑或绝对化表达，如“必须买全套”“不买会很麻烦”。

## 5. GPA/保研/转专业基础信息库

用途：用结构化方式收录 GPA、绩点、排名、推免、转专业等基础政策入口和经验说明。此库只做“信息索引 + 流程解释 + 来源归档”，不替代教务处、学院、辅导员通知。

### 数据库字段

| 字段名 | 类型 | 必填 | 填写说明 |

| 信息类型 | 单选 | 是 | GPA/成绩排名/保研推免/转专业/缓考补考重修/学籍政策/其他 |

| 适用年份 | 文本 | 是 | 如“2026 届”“2025-2026 学年”；不确定写“不确定” |

| 来源发布日期 | 日期 | 否 | 原文件发布时间 |
| 核心结论 | 多行文本 | 是 | 只摘录与学生行动相关的结论，不改写政策含义 |
| 办理/申请入口 | URL/文本 | 否 | 系统入口、表格下载页、学院通知页 |

| 贡献者 | 人员/文本 | 是 | 可匿名 |
| 审核人 | 人员 | 否 | 发布前填写 |

### 填写说明

- GPA、推免、转专业均属于高影响信息，不允许只凭经验发布为正式结论。

- 学院差异要拆条，不把不同学院细则合并成一个“全校规则”。
- 社区页面第一屏必须写明：以学校、学院当年正式通知为准。

## V1 建库执行清单

### 建表顺序

1. 先建“课程数据库”，因为历年卷需要关联课程。
2. 再建“历年卷数据库”，只开放可授权资料。
3. 建“新生生存指南”，先填 20 个最高频问题。
4. 建“GPA/保研/转专业基础信息库”，只放来源入口和流程解释。
5. 建“实验室数据库”，先收录有官网的实验室和公开平台。

### 每条记录发布前检查

- 标题是否能被搜索到。
- 适用对象是否明确。
- 是否有来源材料。
- 是否标明可靠等级。
- 是否有最后复核日期。
- 是否去除隐私。
- 是否存在版权风险。
- 是否能让读者下一步知道该做什么。

### 建议的飞书权限

| 角色 | 权限 |
| --- | --- |
| 普通读者 | 只读、可评论、可提交表单 |
| 贡献者 | 可提交表单、可查看自己投稿状态 |
| 栏目维护者 | 可编辑对应数据库、可初审 |
| 总审核人 | 可发布、下架、修改审核标准 |
| 管理员 | 管理权限、备份、成员变更 |

### 每周维护动作

- 处理新增投稿。
- 复核被评论指出的问题。
- 将“待补充”记录退回贡献者。
- 把已发布条目同步到知识库目录。
- 更新“本周新增/修订内容”。

### V1 不做的事

- 不做教师评分榜、实验室黑榜、课程红黑榜。
- 不做自动推荐“最水课程”“最容易保研路径”。
- 不公开未授权原卷、教材和商业资料。
- 不替代教务处、学院、辅导员的正式通知。
- 不承诺政策结果，只提供来源、流程和经验。
